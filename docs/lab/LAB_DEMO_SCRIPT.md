# STRIX — 10-Minute Stakeholder Demo Script

A click-by-click walkthrough for showing the system to a non-engineer
audience. Assumes the lab is already up per
[LAB_BRINGUP.md](LAB_BRINGUP.md) — this script is what you do *during*
the meeting.

**Audience**: a security director, a CISO, a thesis committee, a customer.
Not engineers — they want the *story*, not the architecture.

**Tabs to pre-open** (do this 30 seconds before the call so you're not
fumbling):
1. http://VM1:3000 — STRIX dashboard, logged in as admin
2. http://VM1:3000/vigilance-feed
3. http://VM1:3000/ai-engine
4. http://VM2:8888 — Caldera UI, logged in as red/admin
5. A terminal SSH'd into your laptop, ready to fire `escalate_demo.py`

---

## ⏱ 0:00 — 0:30 · The pitch (say this verbatim)

> *"Most SOC tools today fall in two camps: SIEMs that drown analysts in
> raw alerts, and EDR products that fire on signatures one host at a
> time. Neither tells you the story of an attack as it unfolds.*
>
> *STRIX sits on top of Wazuh and uses five neural networks — an
> autoencoder, a variational autoencoder, a graph neural network, a
> transformer, and a reinforcement-learning agent — to do three things
> Wazuh alone can't: spot novel anomalies, link related alerts into
> attack chains, and predict the attacker's next move. Let me show you."*

(30 seconds. Don't rush — this is the only slide-style moment.)

## ⏱ 0:30 — 2:30 · Act 1: "What's our security posture right now?"

**Tab**: http://VM1:3000 (Dashboard)

Point at, in order:

1. **Global Risk gauge** (top-right). Read the number aloud: *"Right
   now we're at 0.6 out of 1. That's a composite of four signals" —*
   point at each component below.

2. **Attack Vector chart** (left). *"This is the Cyber Kill Chain
   distribution over the last hour. We have alerts at stage 4,
   Exploitation. Empty buckets at 5, 6, 7 means we haven't seen
   post-exploitation activity yet — this is a developing situation, not
   a finished compromise."*

3. **Sentinel Insight panel** (bottom-right). *"This is generated by
   Claude Opus on demand — natural-language summary of the current
   threat picture. Right now it's a placeholder because the lab's
   Anthropic key isn't set. In production it summarises the top-3
   threats and their suggested response in plain English."* (skim it
   quickly, then move on)

4. **Victim Graph** (centre). *"Hosts under attack. Right now one node
   is showing — VM 3 — because that's the only one that's been hit so
   far."*

> **What to skip**: the Topology page, the Threat Intel page. They're
> nice-to-haves but the dashboard tells the story on one screen.

## ⏱ 2:30 — 5:30 · Act 2: "Let's stage an attack and watch it react"

**Tab**: switch to the Vigilance Feed (http://VM1:3000/vigilance-feed)

> *"Now I'm going to fire a real attack from another VM. Watch the live
> feed."*

In your terminal:

```bash
python3 infra/scripts/escalate_demo.py \
  --redis redis://VM1_IP:6380/0 \
  --delay 2 --n 12 --agent-id 003
```

What you'll see, narrated:

| Time | What appears | What to say |
|---|---|---|
| ~3s | First card slides in: "Active vulnerability scan" | *"There's the first stage. Wazuh detected the recon, STRIX classified it as Reconnaissance — CKC stage 1."* |
| ~6s | Second card: "Exploit public-facing application" | *"Now we're at Exploitation, stage 4. Notice each card shows the AI's confidence score on the right."* |
| ~12s | Cards keep appearing, badge changes colour | *"Watch the colour. The chain is escalating — yellow at stage 4-5, red at 6-7."* |
| ~25s | All 12 cards landed, chain badge says "CKC 7" | *"In 25 seconds the system reconstructed the entire 7-stage kill chain — Reconnaissance through Exfiltration. A human SOC analyst would still be reading the first alert."* |

> **Key sentence**: *"The cards aren't 12 separate alerts. STRIX
> recognised they're one continuous attack against the same host and
> stitched them into a single chain."*

## ⏱ 5:30 — 8:30 · Act 3: "How does the AI think about this attack?"

**Tab**: still Vigilance Feed. Click any card → it deep-links to the
**Attack Analysis** page for that chain.

Show, in order:

1. **Kill-chain Progression strip** (top). *"Each pip is a stage the
   chain has touched. The DQN reinforcement-learning agent decided what
   action to take at each step — monitor, low-alert, escalate, isolate
   the host, or block the user. For our synthetic test it stayed at
   low-alert, but the decisions are real and traceable."*

2. **Graph Evolution panel** (middle-left). *"The GNN is rebuilding the
   attack graph every 30 seconds. It's not just 'what happened' — it's
   'what's connected'. If the same attacker hits a second host, the
   graph would link them."*

3. **AI Predictions panel** (middle-right). Read aloud the
   `predictedNextStageName` and the confidence percentage. *"The
   transformer is predicting the next move. Right now it's saying X
   with Y% confidence. In a real incident, this is what you'd act on
   — pre-positioning your response before the attacker gets there."*

4. **Forensic Logs** (bottom). *"Every individual alert that contributed
   to this chain. Clickable, timestamped, paginated. This is what the
   SOC writes their incident report from."*

5. **Bottom metrics bar** — point at *Dwell Time*. *"This is the metric
   that matters in real-world SOCs — how long an attacker has been
   inside before you noticed. Industry average is 200+ days. We caught
   this in seconds because the chain was open from the first stage."*

---

## ⏱ 8:30 — 9:30 · Act 4: "Show me the AI is real"

**Tab**: AI Engine page (http://VM1:3000/ai-engine)

Quick tour — don't dwell:

1. **Model registry** (top). *"Five models, each pinned to a SHA-256
   hash. If anyone swaps a model file out, the system refuses to
   start. That's how you make ML auditable."*

2. **Drift panel**. *"Each model gets a drift score in real time —
   KL-divergence between today's predictions and the training
   distribution. Cross the threshold, the system pages you."*

3. **Live telemetry strip**. *"This is per-second inference throughput.
   We're sustaining ~200 alerts per second on a single CPU shard. Add
   GPU shards and it scales horizontally."*

> **Sentence to land**: *"This isn't a chatbot wrapper. There are five
> distinct models doing five different jobs, each independently
> monitorable, each retrainable on its own cadence."*

## Recovery moves if something breaks mid-demo

| Breaks at | Pivot |
|---|---|
| Vigilance Feed shows nothing for >10s | *"Live SSE connection — let me refresh"* (Cmd+R the tab; events buffer in Redis and replay) |
| Attack Analysis page shows empty graph-evolution | Pick an older chain from the chain list — newer chains take 30s for the first snapshot |
| Caldera attack doesn't fire | Skip Act 2, jump straight to `escalate_demo.py` — it's deterministic |
| API returns 500 | `docker logs strix_api \| tail -20` in your terminal, point at the line, *"and that's why we have observability"* — turn it into a feature |

---

## What NOT to say (audience traps)

- **Don't oversell auto-response.** The DQN *recommends* actions — auto-response is `disabled` by default in this build because the lab doesn't have a kill-switch operator. If asked: *"It's a recommendation engine; auto-execution is gated behind explicit operator approval."*
- **Don't claim "0 false positives".** Quote the drift panel instead — *"we monitor and bound the error rate, we don't pretend it's zero."*
- **Don't show the Threat Intel page** unless asked — it's empty without API keys, and explaining why kills momentum.
- **Don't dive into the model architecture diagram** unless asked twice. Save it for the second meeting.

## Pre-flight checklist (run 5 min before the demo)

```bash
# 1. All services up?
docker compose -f infra/compose.lab.yml ps | grep -v "Up\|healthy" && echo "❗"

# 2. Frontend reachable?
curl -fsS http://localhost:3000/ -o /dev/null -w "web: %{http_code}\n"

# 3. Recent data in the dashboard? (avoid a "0 alerts" demo)
python3 infra/scripts/escalate_demo.py \
  --redis redis://localhost:6380/0 --delay 1 --n 6 --agent-id demo-warmup

# 4. Caldera reachable from your browser?
curl -fsS http://VM2_IP:8888 -o /dev/null -w "caldera: %{http_code}\n"
```

If any of those return non-200 — stop, fix it, *then* start the demo.
A broken demo is worse than a postponed one.
