## Mobile UI changes (in chronological order)

### 1. Tab bar simplification
- Dropped the `ACTIONS` primary tab — it now lives as a row inside the
  **More** hub ([apps/mobile/app/(tabs)/more.tsx](../../apps/mobile/app/(tabs)/more.tsx)).
- Removed the focused-state background pill that was overflowing on
  narrow phones. Active tab is now: icon recolours + small 4×4 dot
  appears under the glyph. Same height for active and inactive (transparent
  dot when inactive) so there's zero layout jump on tab switch.
- Added `Ionicons.loadFont()` + a stateful `ionLoaded` flag and an
  emoji fallback (`🏠 🔔 📂 ⋯`) — Expo Go on iOS SDK 54 with the new
  arch occasionally fails to register Ionicons even after `useFonts`
  resolves; the fallback keeps the bar from going blank.

### 2. Alerts badge
- New `alertsBadgeBaseline` field in [stores/ui-store.ts](../../apps/mobile/stores/ui-store.ts).
- Alerts screen calls `markAlertsSeen(unackCount)` inside a `useFocusEffect`
  so the badge drops to 0 the moment the user opens the tab. New
  incoming alerts beyond the baseline still surface.

### 3. Filter pills (cases / alerts / feed / actions)
- **Root cause** of the "vertical capsule" shape: `borderRadius: 9999`
  on chips with no fixed height. In a horizontal ScrollView the default
  cross-axis is `stretch`, so the moment any sibling grew taller, every
  pill stretched too — and 9999 radius then drew them as tall ovals.
- Fix: `height: 32`, `borderRadius: 16`, `alignItems/justifyContent:
  center`, `numberOfLines={1}` on labels, `includeFontPadding: false +
  textAlignVertical: center` to kill Android baseline padding drift.

### 4. Dark mode propagation
- `feed.tsx`, `search.tsx`, `status.tsx` were importing the static
  `colors` palette directly — never reactive to `isDark`. Rewrote to
  call `useColors()` and apply colors inline. Status bar style now
  reactive too via a `<ThemedStatusBar/>` component in the root
  `_layout.tsx`.

### 5. Model Health page rewrite ([status.tsx](../../apps/mobile/app/(tabs)/status.tsx))
- Pulled the **same training-time metrics** the web AI-engine page
  shows. New file: [apps/mobile/lib/model-registry.ts](../../apps/mobile/lib/model-registry.ts),
  a hand-mirror of [apps/web/lib/model-registry.ts](../../apps/web/lib/model-registry.ts)
  with AE / VAE / GNN / Transformer / STRIX entries (accuracy, F1,
  AUC, precision, recall, threshold, model-specific extras).
- Removed the `· v{version}` suffix next to each model's name (per
  request).
- New top KPI strip: Composite Accuracy / Composite F1 / Avg Drift KL.
- Per-model card now shows **ACC / F1 / AUC / DRIFT** in a strip; drift
  flips red above 0.2 KL.
- Expandable "View details" → precision, recall, threshold, registry
  extras, live latency (P50/P99), last health check, weights SHA-256,
  source path.

## Notifications wiring

### Decision: Expo Push (kept), not bare Firebase FCM
- Backend already speaks Expo Push via [expo_push_adapter.py](../../apps/api/src/strix_api/adapters/expo_push_adapter.py)
  — which **relays to FCM (Android) / APNs (iOS)**. Same delivery
  network as `@react-native-firebase/messaging`, thinner wrapper.
- The reason system push wasn't working from Expo Go wasn't the
  protocol — it was that Expo Go SDK 53+ strips `expo-notifications`'
  remote-push module at runtime. Same wall applies to `@react-native-firebase/messaging`
  inside Expo Go. The fix is the dev build, not switching protocols.

### Expo Go safety
- All `expo-notifications` access now routes through `tryGetNotifications()`
  in [services/notifications.ts](../../apps/mobile/services/notifications.ts).
- On Expo Go (detected via `Constants.executionEnvironment === "storeClient"`),
  the accessor returns `null` and every caller early-returns. Without
  this guard, the import itself hard-errors on Android Expo Go SDK 53+.
- `[push] No EAS projectId` warning quieted to fire at most once per
  session.

### Local in-app pings
- New hook: [useLocalAlertPings.ts](../../apps/mobile/hooks/useLocalAlertPings.ts).
  Subscribes to the live SSE feed and fires a local system notification
  for any event with `vaeMaliciousProb ≥ 0.7` OR `ckcStage ≥ 4`.
- Dedupes by `alertId`. Primes its seen-set from the SSE backfill so
  cold start doesn't flood the user with notifications for events
  already on the screen.
- Works in Expo Go (local notifications still allowed); fires regardless
  of FCM setup. Foreground pings ride this path.

### Real system push (background + killed app)
- Needs the dev build + FCM credentials, set up below.

  patterns weren't anchored to root, so they also matched
  `apps/mobile/assets/icon.png` and friends. Fixed by anchoring with
  leading slashes: `/*.png`, `/*.jpg`, `/*.svg`, …

  `cavix-app`.

  `google-services.json` to [apps/mobile/google-service/google-services.json](../../apps/mobile/google-service/google-services.json)

- Uploaded the service account key to EAS server-side via
  `npx eas-cli credentials` → Google Service Account → Manage for FCM V1

## Local Android emulator setup

- AVD created: `cavix_pixel` (Pixel 9 profile, android-36
  google_apis_playstore x86_64). Lives at `~/.android/avd/cavix_pixel.avd/`.
- User `yacine` added to the `kvm` group (KVM acceleration).
- `.zshrc` got an `ANDROID_HOME` / `ANDROID_SDK_ROOT` block plus
  `$ANDROID_HOME/{cmdline-tools/latest/bin, platform-tools, emulator,
  build-tools/36.1.0}` on `PATH` — `avdmanager`, `sdkmanager`,
  `emulator`, `adb` now resolve without the full path.
- Boot command: `emulator -avd cavix_pixel -no-snapshot -gpu
  swiftshader_indirect &`. Hardware GPU paths cause Vulkan-related
  hangs on Kali; SwiftShader Indirect is the stable fallback.
